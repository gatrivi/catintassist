# Fix: call-log import (Settings → Data) actually corrects today's stats

## Root cause
- `mergeImportedDays` today-branch (`src/utils/callLogImport.js:194-211`) uses `Math.max(prevDaily, d.billableMins)` — importing a *lower* corrected value never takes effect (dev seed + over-banked live minutes both mask it).
- Today's entry is never written to `dailyLog`/`historyTimeline` — timeline/heatmap don't repaint for today's import.
- `devStatsSeed.js` hardcodes today 59m/4 calls on localhost, compounding the no-op.

## Changes (v4.87.4)
1. **`src/utils/callLogImport.js` — today branch becomes authoritative:**
   - `dailyMinutes`/`callsToday` = imported values (overwrite, not max). Import IS the correction.
   - monthly/weekly adjust by real signed delta (`nextDaily - prevDaily`, floored so totals never go below 0).
   - Also write today into `dailyLog[dateStr]` and `historyTimeline[dateStr]` (same as past days) so the progress-bar timeline repaints with the imported call segments.
   - Update the function's doc comment.
2. **Remove dev seed collision:** delete `src/utils/devStatsSeed.js` call from `src/index.js` (and the file) — import now covers its purpose; it can only mask corrections.
3. **`CallLogImportPanel.js`:** flash message already shows days/calls/mins — extend to show old→new daily minutes so you can verify the correction took.
4. **Tests:** update `src/utils/callLogImport.test.js` — today-overwrite (up and down), signed monthly delta, today timeline write. Run `npm test`.
