# Echo fix — greetings heard twice (2026-09-17, v4.128.0)

## Symptom
Every caller greeting sounded twice to the interpreter → unusable, patient-risk.

## Root cause (2 independent copies)
1. **App played local + sink in parallel** on every caller fire
   (`OnCallSoundboardStrip`, `GreetingEditorView` caller test, `useTTS`, Studio mixed sends).
2. **Mixer looped the sink copy back**: VAIO → **A1+B1** while A1 = CABLE Input,
   so each greeting also entered the STT cable (2nd delayed copy + self-transcription).
   Empty Strip[1] also routed →A1+B1.

## Fix
- Caller-bound audio is **sink-only by default**. Opt-in local copy: **Monitor**
  checkbox on the on-call strip (pref `CATINT_CALLER_MONITOR`, default off).
  Previews (🔊 You, mic-test) unchanged and audible.
- Mixer (applied live, backup in %TEMP% `catint-voicemeeter-before-2026-09-17-*.xml`):
  VAIO → **B1 only**; empty Strip[1] → nowhere. `setup-voicemeeter-mic.ps1 -Apply` enforces both now.
- **Still manual:** A1 = CABLE Input → point it at your headset in Voicemeeter UI
  (Remote-API device stepping is broken, UI only). Harmless now that nothing routes to A1.
